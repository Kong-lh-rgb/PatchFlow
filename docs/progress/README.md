# 开发进度记录规则

本目录是 PatchFlow 的强制开发日志，与代码一起保存在 Git 工作区中。规则如下：

1. **每个自然日一个文件**：`docs/progress/YYYY-MM-DD.md`，使用当天真实日期。
2. **完成即记录**：每完成一个“可以独立验证的开发任务”，必须立即追加一条完成记录，不允许一天结束后凭记忆补写。
3. **任务粒度**：安装一个依赖或运行一条命令不算独立任务；完成一个 Package、接口、测试或配置闭环才算。
4. **必须可验证**：记录必须包含真实验证命令和结果，不能只写“已完成”。
5. **如实记录失败**：未完成或失败的工作也要记录原因和下一步，不伪造成功。
6. **收尾总结**：每次准备结束工作前，补充“今日总结”和“下一步”。
7. **不篡改历史**：修改已有功能时，在当天（新）进度文件中追加新记录，不修改过去日期文件中的事实。

## 文件模板

```markdown
# YYYY-MM-DD 开发进度

## 今日目标

- [ ] 目标一
- [ ] 目标二

## 完成记录

### 任务 N：任务名称

- 状态：完成 / 部分完成 / 阻塞
- 完成内容：具体说明实现了什么
- 关键文件：列出主要文件路径
- 技术决策：记录重要选择及原因；没有则写“无”
- 验证方式：实际执行的命令
- 验证结果：通过项、失败项和必要输出摘要
- 遗留问题：当前未解决的问题；没有则写“无”

## 今日总结

- 完成了什么：
- 当前风险：
- 下一步：
```
