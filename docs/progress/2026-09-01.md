### 任务 4：tools 包——PathGuard 路径防护

- 状态：完成
- 完成内容：`createPathGuard()` 提供两级防护——`resolve()` 词法层（拒绝绝对路径、`..` 越界、NUL、空路径）与 `resolveReal()` 符号链接层（对最深“已存在祖先”做 realpath 后校验仍在 realRoot 内，未存在尾段不可能是指向仓库外的链接）；错误用 `PathGuardError` 携带 `INVALID_PATH` / `PATH_ESCAPE` / `SYMLINK_ESCAPE` 错误码；`pathGuardFailure()` 把防护错误折叠为统一的 ToolResult 失败。同时把共享类型从 index.ts 拆到 types.ts 避免循环导入。
- 关键文件：`packages/tools/src/path-guard.ts`、`packages/tools/src/path-guard.test.ts`、`packages/tools/src/types.ts`
- 技术决策：符号链接校验只 realpath 已存在祖先——未存在的尾段不可能指向仓库外，且 macOS `/tmp → /private/tmp` 场景由 realRoot 对比天然覆盖；工具的文件访问统一走 `resolveReal()` 返回的真实路径。
- 验证方式：`cd packages/tools && npx vitest run src/path-guard.test.ts`
- 验证结果：18 个测试通过（合法解析、`../` 多种变体、绝对路径、NUL、指向仓库内/外的目录与文件符号链接、未存在路径的祖先校验、错误码区分）。
- 遗留问题：无

### 任务 6：tools 包——search_code ripgrep 工具

- 状态：完成
- 完成内容：spawn `rg`（无 Shell、参数数组、`--` 防前导 `-` 被当作选项）；`-n --no-heading --no-messages --color never`，默认大小写不敏感（`-i`），`isRegex=false` 时 `-F` 字面量；`--glob` 显式排除 node_modules/dist/.git；结果条数（默认 50）与总字符数（20000）双上限，达到即提前 SIGTERM 终止 rg；超时 10s 兜底；目录与单文件均可作为搜索目标。
- 关键文件：`packages/tools/src/search-code.ts`、`packages/tools/src/search-code.test.ts`
- 技术决策（测试暴露的三个真实缺陷及修复）：
  1. **字符上限必须“先判断再计入”**：先 push 再检查会让单条 30k 字符的行完整进入输出（summary 30105 字符），改为预算判断后严格有界。
  2. **单文件搜索时 rg 省略文件名前缀**（输出 `1:axb`），解析 `file:line:content` 失败导致误报“未找到匹配”；加 `--with-filename` 强制带前缀。
  3. 本机 `rg` 原本只是 Claude Code 的 shell 包装函数、PATH 无真实二进制（Node spawn ENOENT），已 `brew install ripgrep`（15.2.0）。
- 验证方式：`npx vitest run src/search-code.test.ts`；根目录 `pnpm test`
- 验证结果：17 个测试通过（大小写、正则/字面量、目录限定、忽略目录、无匹配、双上限截断、前导 `-` pattern、越界拒绝、非法输入）。
- 遗留问题：rg 不存在时返回 ok:false 与安装提示（该路径暂无自动化测试，属可接受的降级路径）。
